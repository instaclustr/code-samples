# Shoe Store Support ChatBot: MCP Gateway Rate Limiting Sample

A **AWS Bedrock + Streamlit** chatbot that connects to the **NetApp Instaclustr MCP Gateway**
over Streamable HTTP. This is the companion code for the tutorial
*"MCP Gateway Rate Limiting: Token-Bucket Limits for AI Agents"*, building on
[shoe-store-support-chatbot](../shoe-store-support-chatbot) and
[shoe-store-support-chatbot-rbac](../shoe-store-support-chatbot-rbac).

## What it demonstrates

The agent sends bursts of calls through the `supportchatbot` virtual server, first with no
rate limit and then with token-bucket limits. The `instaclustr-api` backend lets the same
agent read the Kafka topic and Cassandra table metrics that show the effect.

- `ordersapi` (HTTP): `get_orders`
- `supporttickets` (Kafka): `submit_request`, with a tool-level rate limit
- `catalogdata` (Cassandra): `get_product_details` and `get_supplier_cost`, with a backend-level rate limit
- `instaclustr-api` (Instaclustr API): read-only tools generated by MCP Gateway

```
Streamlit shoe-bot  ──Streamable HTTP──▶  MCP Gateway "supportchatbot" Virtual Server
                                             ├── ordersapi       (HTTP)             → get_orders
                                             ├── supporttickets  (Kafka)            → submit_request (rate limited)
                                             ├── catalogdata     (Cassandra)        → get_product_details, get_supplier_cost (rate limited)
                                             └── instaclustr-api (Instaclustr API)  → listActiveClusters, getClusterMetrics, ...
```

## Prerequisites

- The MCP Gateway setup from the previous samples: the `supportchatbot` virtual server with
  the `ordersapi`, `supporttickets` and `catalogdata` backends, and no OAuth or Access Control
  Lists enabled
- An `instaclustr-api` backend, created with a Read Only Provisioning key and a Monitoring key
- A running Kafka cluster and a running Cassandra cluster
- Python 3.11+ and [uv](https://docs.astral.sh/uv/)
- An AWS account with Amazon Bedrock model access for the configured model and region

## Quick start

```bash
cp config.example.json config.json   # fill in your MCP Gateway URL and cluster names
uv sync
export AWS_ACCESS_KEY_ID="..."
export AWS_SECRET_ACCESS_KEY="..."
export AWS_DEFAULT_REGION="us-east-1"
uv run streamlit run src/shoe_bot/app.py
```

Open http://localhost:8501. The sidebar should say **Connected · 25 tools**.

## Configuration

`config.json` has three parts:

- `bedrock`: region, model ID, system prompt and agent loop settings
- `mcp.servers`: your MCP Gateway endpoint (`https://mcp-gateway.<id>.cnodes.io/chatbot`)
- `ui`: display-only settings, including the Kafka and Cassandra cluster names, topic and
  table used by the quick prompts, an optional alias map for display names, and the default
  state of the **Mask sensitive values** toggle

AWS credentials are not stored in `config.json`. Use the standard AWS credential chain
(environment variables, `aws configure` or an IAM role).

## Quick prompts

| Button | What it does |
|--------|--------------|
| Topic rate (before / after) | Reads the Kafka topic's message rate with the Instaclustr API tools |
| Flood: 50 escalations | Asks the agent to file 50 separate support requests |
| Refill test (1 request) | Files one support request to check that the bucket has refilled |
| Flood: 40 lookups + metrics | Runs 40 product lookups, then reads the Cassandra read metrics |
| Supplier cost | Looks up the supplier cost for SHOE-001 |
| Product details | Looks up the details for SHOE-001 |
| Cassandra cluster details | Reads the Cassandra cluster details with the Instaclustr API tools |
| Which clusters are running? | Lists your active clusters with the Instaclustr API tools |
| Cluster details | Lists your active clusters with more detail per cluster |
| Kafka cluster details | Reads the Kafka cluster details with the Instaclustr API tools |

Run each flood once with no rate limit and once with the limits set, and click **Clear chat**
between runs.
